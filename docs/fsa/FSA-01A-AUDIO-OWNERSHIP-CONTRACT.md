## Explicit future ownership boundaries

**Native Reviewer owns the presentation and its native media lifetime.** CardMediaPlayer/AndroidTtsPlayer, existing legacy fallback and existing WebView/video retain actual playback ownership. A future Reviewer-scoped voice coordinator owns only transient request generations, phase and eligibility; it does not create TextToSpeech, MediaPlayer, AudioTrack or an independent focus request.

A single **native audio lease/focus boundary within the existing media lifecycle** must coordinate all supported playback and mic ownership. Existing SoundTagPlayer acquisition/abandonment would delegate to that one boundary if later integration is approved; do not leave it requesting focus concurrently with another new controller. Native TTS and legacy paths must participate in the same policy or stay unsupported for automatic handoff. Extending that native boundary is a future implementation decision, not an existing class/API or a source AudioFocusController import.

An input lease is mutually exclusive with native playback/recording and requires permission, supported foreground state, current profile/collection/card/side/presentation, verified route policy and settled cancellation. Focus does not itself grant microphone permission or prove silence. User replay/manual rating/navigation and profile switch invalidate the voice generation before cancelling old work. Focus may be abandoned after a playback group while its lease still prevents input until completion/gap checks finish. A new playback operation supersedes pending input.

## Completion semantics and platform scope

- TextToSpeech.speak success acknowledges queuing; it is not synthesis or playback completion. Audio chunks/onBeginSynthesis are production events, not quiet-output events. The [platform TTS reference](https://developer.android.com/reference/android/speech/tts/TextToSpeech) distinguishes these asynchronous operations.
- For speak requests, the [UtteranceProgressListener contract](https://developer.android.com/reference/android/speech/tts/UtteranceProgressListener#onDone(java.lang.String)) describes onDone after audible playback; synthesizeToFile onDone means file writing finished. onAudioAvailable/onBeginSynthesis arrive before audio may play. onStop is a separate cancellation/flush outcome. Do not substitute the synthesis-queue-completed broadcast for playback completion.
- onDone is available from API 15, onStop from 23, synthesis/chunk callbacks from 24; target minimum24 covers those but engine callback correctness still requires acceptance. A fixed extra gap covers acoustic/route tail conservatively; it is not a universal Bluetooth latency or echo-cancellation guarantee. Missing/ambiguous callbacks time out to blocked/manual mode.
- MediaPlayer completion and HTML-video events pertain to their streams, not every other engine or card script. QUEUE_FLUSH/stop address their own playback scope; one engine flush does not prove another is quiet. Native AndroidTtsPlayer explicitly stops the prior engine when switching.
- [Audio focus](https://developer.android.com/media/optimize/audio-focus) differs across API levels: compat handling is needed for 24/25, AudioFocusRequest APIs begin 26, newer Android enforces additional behavior. For apps targeting35+, focus requests require the top app or an eligible FGS. Speech content/ducking and actual focus callbacks must be tested; an empty native listener is not a complete interruption policy.
- [SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer) needs main-thread calls, RECORD_AUDIO and destruction at end of use. On-device APIs31/support/download33/language extras34 require guards. Preference for on-device/offline does not establish a strict offline policy. [Microphone FGS restrictions](https://developer.android.com/develop/background-work/services/fgs/service-types) remain a separate unapproved background feature; first support should remain foreground and opt-in.

These are platform contracts consulted 2026-11-13 and observed source behavior, not a certified engine/device matrix. Automatic handoff remains disabled wherever output ownership, focus, callback identity or physical route is unknown.

## Proposed transition table — not an existing application state machine

IDLE -> SPEAKING -> COMPLETING -> LISTENING -> PROCESSING -> IDLE is a **possible successful voice interaction**, not the native scheduler. Actual implementations require STARTING, CANCELLING and BLOCKED states too. Native Reviewer remains the only study-state authority; these states cannot select/advance cards or persist ratings.

All engine/recognizer/route callbacks must marshal into one serialized native-owner coordination context before state changes or dispatch; no callback thread independently opens the mic or rates. Every accepted event carries owner lifecycle, profile/collection, card/presentation, side, request generation and operation/engine identity. A current request may accept one terminal outcome only. Native callbacks lacking that identity are insufficient inputs until a future adapter can establish it. Timeout budgets use a monotonic clock; device/engine-specific bounds require later measurements.

| ID | From / event | Required guards and action | Next / observable outcome |
|---|---|---|---|
| A01 | IDLE / explicit voice session or permitted native playback | Native owner active/current; mic closed; observe/request through existing playback owner; acquire one native output lease/focus policy. | STARTING; no mic. |
| A02 | STARTING / native playback actually starts | Matching operation/engine, focus granted where required; no recorder or mic lease. | SPEAKING; input disabled. |
| A03 | STARTING / no playable media | Explicit native no-output result, not a generic completion callback; current side/request and permission still valid. | COMPLETING with no-output reason; no invented audible-success claim. |
| A04 | SPEAKING / final successful output completion | Correlated last item across all supported native/legacy/video paths; no cancelled/failed/remaining output; do not consume group finally alone. | COMPLETING; microphone stays closed. |
| A05 | COMPLETING / gap and output settling finish | Recheck identity/side/lifecycle, route generation, no queued/active native or script audio, permission and exclusive mic lease; known successful/no-output reason. | LISTENING; start exactly one generation-bound STT request. |
| A06 | LISTENING / end of speech or PTT release | StopListening only; keep request owned until a final result/error. Release must not submit/rate; cancelled gesture is cancellation. | PROCESSING; no new recognizer start. |
| A07 | PROCESSING / one matching final STT result | Terminal consumption once; validate current native phase and presentation; interpret text or request an existing native action. Provider result is advisory. | IDLE after dispatch request; native completion/failure observed separately, never equated with a handled Boolean. |
| A08 | PROCESSING / authorized feedback playback | Independent current playback request through native owner; no pending mic lease. | STARTING; same ownership checks as A01. |
| A09 | Any active state / pause, destroy, card/profile/side switch, manual action, cancel, headset loss, focus loss, permission revocation | Invalidate generation first; cancel recognizer/retry/gap/provider work; stop supported native output/recording as appropriate; no automatic route-to-speaker fallback for private speech. | CANCELLING; no mic or native rating from obsolete work. |
| A10 | CANCELLING / all owned work settled | Release relevant native leases/focus; discard any late result. Restart needs fresh current intent. | IDLE; no automatic listen/resume. |
| A11 | Any state / denial, missing engine/model, ambiguous/failed callback, output error, timeout/network failure | Invalidate generation; cleanup as A09. Unknown quiet/focus/route state cannot pass handoff guards. | CANCELLING then BLOCKED/manual mode. |
| A12 | Any state / stale or duplicate completion/result | Reject wrong generation/engine/operation/side or already consumed terminal event. | No transition, no mic start, no rating. |
| A13 | BLOCKED / explicit retry after cause resolved | New native snapshot/generation; permission/privacy/route/foreground policy satisfied; old jobs settled. | IDLE then A01; never replay a stored action. |

Headset reconnect updates observation only; it cannot restore an invalidated turn or automatically select a mic. If an actual output route changes during the gap, A09 wins. Foreground loss follows A09 even if a source START_STICKY service might remain alive. An independently authorized background feature must define a new lifecycle contract before relaxing this rule.
